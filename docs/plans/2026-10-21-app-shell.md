# Remora app shell: plan 2a, as built

**Date:** 2026-10-21
**Status:** Built, checked against the user's account, reviewed twice (RMKit and app) and merged.
**Design:** `2026-10-21-remora-design.md`. This covers M1 build steps 3–5 (library window, notebook window, `rmr://` links) and the RMKit carryovers from plan 1's final review.

Unlike plan 1, this plan wasn't written as transcribe-me code first. Every piece was proven in a scratch clone (tests, a running app on the real account, screenshots of its windows), then committed as four commits. Reviewers check the commits against this document and the design.

## What's in it

**1. RMKit carryovers** (`fix(rmkit): plan 1 final-review carryovers`)
- `Library.build` throws on errors that fail every request (`CloudError.failsEverything`: 401, 402/403, 429, 5xx, `URLError`), so the caller keeps its old library. An item that fails on its own keeps its previous version and is listed in `failures`.
- `CloudError.offline` means "not in the cache" and is per item.
- `Library.isInTrash` walks parents, so the contents of a trashed folder count as trashed.
- `CloudSession` remembers a failed token exchange for `failureCooldown` (30 s) and fails fast meanwhile, because the exchange is rate-limited.
- `BlobStore`:
  - one fetch per hash at a time (a `FetchGate` actor), at most 8 at once;
  - each file except `.docSchema` is checked against its SHA-256 before it's cached (schema 3 hashes entry lists as their children's hashes);
  - this passed on a cold cache against the whole real library.
- `ItemMetadata` requires only `visibleName`, `parent` and `type`.
- `Keychain.set(_:account:label:)` and `label(account:)` keep the account's email beside its token.

**2. Templates** (`feat(rmkit): draw the built-in page templates`)
- The families: `P Lines small/medium/large`, `LS Lines small/medium`, `P Grid small/medium/large`, `P Dots S`, `P Dots large`, and `Blank`/`blank`.
- Spacing and offsets come from the formulas in reMarkable's template definitions (read from the installed desktop app's bundled JSON, nothing copied). Offsets are expressed through `paperOriginX = W/2 − H/2`.
- Lines are black, 1 px, antialiased. Dots are about 2 px, not antialiased.
- Templates the user's library uses that are not drawn: `P Checklist`, `P Margin medium`, `Isometric`. The window shows the name instead.
- Checked by eye on a portrait lined page and a landscape grid page from the user's library; the handwriting sits on the lines.

**3. App support in RMKit** (`feat(rmkit): links, account sync, …`)
- **`RemoraLink`:** parses and formats `rmr://doc/<id>[?page=<id>]` and `rmr://folder/<id>`, and refuses any id that isn't `[A-Za-z0-9-]`. Its Markdown form escapes brackets.
- **`AccountSync` (actor):**
  - `loadCached()` builds the library from the cache alone, using the last root kept in `<account>/root.json`;
  - `refresh()` re-reads the root, rebuilds what changed, persists the root and trims the cache.
- **`Library.folders(under:)`:** the outline tree. **`Library.search(_:)`:** matches names, then tags, then folder paths.
- **`Document.render(_:scale:blobs:)`:** a page with its template under the ink. A blank page is its template alone.

**4. The app** (`feat(app): the Remora app shell`)
- **Build setup:**
  - `project.yml` (XcodeGen): ad-hoc signed by default, not sandboxed, the `rmr` URL scheme, the local RMKit package.
  - `scripts/build-app.sh` builds into `~/Library/Developer/Xcode/DerivedData/Remora-local`, never in-tree (the checkout is on an SMB share) and never under `/tmp`, where LaunchServices won't bind URL schemes.
  - `REMORA_SIGN_IDENTITY` and `REMORA_TEAM` sign with a real identity, so Keychain "Always Allow" survives rebuilds. The user's builds use their Developer ID; no team id is committed.
- **Routing:** as found by the routing spike.
  - Document windows are a `WindowGroup(for: DocumentLink)` whose identity is the document only. The page travels separately through `Router.pageRequest`, with a nonce so a repeated link scrolls again.
  - The launch URL arrives through `application(_:open:)`. Once launched, `kAEGetURL` is taken from SwiftUI, which otherwise re-shows the Library on every link.
- **Library window:**
  - the sidebar lists each account (labelled by email), with Library, Pinned and its folder tree;
  - the table shows name, modified, kind and pages;
  - search covers the whole account;
  - the context menu has Open, Copy Link and Copy as Markdown Link;
  - Refresh is Cmd-R;
  - a pairing sheet asks for the code from my.remarkable.com/device/desktop/connect;
  - a sync problem shows as a banner.
- **Notebook window:**
  - pages in a lazy column, fit to width, zoom with Cmd − / 0 / + or a pinch;
  - the current page is the topmost one more than a third visible;
  - "Page N of M" in the subtitle;
  - Copy Link to Page (Cmd-L), Copy as Markdown Link, Copy Link to Document;
  - pages render off the main thread, re-rendered at 256-px width steps;
  - a badge marks an undrawn template, and a warning marks a lossy page.
- **PDF and EPUB documents** open a placeholder, until plan 2b.

## Checked on the real account

- The library window lists the account (`gabor.veres@gmail.com`). An account paired before labels existed gets its email looked up once, through its existing session.
- `open 'rmr://doc/<inbox>?page=<p2>'` opens one Inbox window at page 2, showing "Page 2 of 2". A second link to page 1 scrolls the same window.
- "Quick sheets", 53 pages on an Isometric template, shows the template badge, scrolls lazily, and renders coloured ink.
- Each commit builds and its tests pass: 75, 78, 84 and 84.

## Known limits (`ponytail:` or deferred)

- A blank page has no size of its own and is drawn at the rm2 size. Paper Pro pages share its 3:4 shape.
- There is no image cache: pages scrolled back into view render again.
- The proof of URL handling didn't cover state restoration of document windows across relaunch.
- Live refresh: sync runs at launch and on Cmd-R only.
- Review items deferred:
  - The last pages of a document can't become "current" when their top never rises to a third of the window (several pages per screen at low zoom, or landscape pages in a narrow window).
  - Zoom keeps the page but not the position within it.
  - A folder link that no account knows waits silently.
  - Remove Account is only on the account header's context menu.
  - `Router.pageRequest` is never cleared.
  - The legacy always-on scrollbar width isn't subtracted from fit-width.
  - Shortcuts live on toolbar buttons rather than a menu with `@FocusedValue`.
  - `FetchGate` doesn't cancel a waiting caller (`ponytail:`).
  - `P Lines` on a page turned landscape spans the full width (`ponytail:`).
  - The cache is trimmed on every refresh; trim less often once the 30 s poll lands.

## Next: plan 2b

1. **PDF and EPUB overlay.** PDFKit draws the page and the ink goes on top, using the rule measured on the user's documents:
   - v6 ink is anchored to the crop box at a fixed `k = 72/227` pt per device px, from the top centre: `u = Wd/2 + x_c·k`, `v = y·k`. Wd and Hd swap for `/Rotate` 90/270. No clipping.
   - v3/v5 pages fit the 1404×1872 screen from the top-left.
   - The same fix applies to rm2agent's export: its fit-to-screen `pdfPageFit` is wrong for v6.
2. Typed-text layer and PDF text selection.
3. Live view: the notification socket, a 30 s root poll, per-page redraw and change markers.
4. Grid view with lazy thumbnails, and offline indication.
5. Page image cache, and Copy Page as Image.
