**Date:** 2026-10-22
**Status:** Built and checked on the user's account. Reviewed (RMKit and app), review fixes applied.
**Design:** `2026-10-21-remora-design.md`. Follows `2026-10-21-app-shell.md` (plan 2a).

As in plan 2a, each piece was proven in a scratch clone (tests, a running app on the real account, screenshots), then committed.

## What's in it

**RMKit**
- **Highlights:** v6 glyph items (block 0x03, item type 0x01) are parsed into `RMPage.highlights` and normalized to rectangles in page coordinates.
  - FlatRenderer draws them under the strokes, one transparency layer each.
  - SVG ignores them on purpose, so it stays byte-identical with rm2agent.
  - An unreadable glyph block counts toward `PageDrops.unreadableBlocks`. `isLossy` therefore means "content may be missing", not only ink.
- **`PDFPlacement`:** where ink lands on a PDF page, measured on the user's documents.
  - v6: a fixed `k = 72/227` pt per device pixel from the top centre of the crop box.
  - v3/v5: the page fitted to the 1404×1872 screen from its top-left, a wide page turned upright.
  - rm2agent's centred fit is wrong for both.
- **Landscape v3/v5 notebooks:**
  - v3/v5 ink is stored in portrait-screen coordinates even in a landscape document. The tablet shows such a document turned a quarter clockwise, so `PageGeometry.toPage` turns it the same way.
  - `PDFPlacement` turns it back, so the measured PDF rule sees the raw screen coordinates.
  - v3/v5 ink on a landscape *PDF* is unmeasured (`ponytail:`).
- **`Document.pdfFile`:** the PDF a PDF or EPUB document's pages sit on.
- **`ChapterLinks`:** where an EPUB chapter link goes; see below.
- **Live: `CloudSession.changes()`** yields on each SyncComplete from another device (the notification websocket), and every 30 s regardless.
  - It buffers at most one pending change.
  - The socket reconnects with backoff, pings every minute and treats a missed pong as dead. It is reopened hourly.
  - A token is replaced only when the handshake is refused.
- **`AccountSync.refresh()`** trims the cache at most every ten minutes, not on every poll.

**App**
- **PDF and EPUB windows:**
  - PDFKit draws the pages, assembled in the tablet's order (pages copied from the source PDF, blank pages where the tablet inserted them). An EPUB shows the PDF the tablet rendered from it.
  - An `InkOverlayView` per page draws ink and highlights as vectors through `PDFPageOverlayViewProvider`. An inserted page also gets its template.
  - PDFKit lays an overlay on the page before the page's /Rotate turns it, while ink is drawn on the page as shown, so the overlay maps the shown page back onto the unturned one. Before this fix, ink on a /Rotate 90 page came out turned a quarter.
  - Live edits redraw only the changed pages, keeping the old ink until the new has loaded.
  - A change to the pages themselves (added, removed, moved, or a new PDF) rebuilds the view and stays on the page being read.
- **Links inside PDFs:**
  - A copied page's link annotations lose their target page. When a page comes on screen, each jump is pointed again, from the source page's annotation, at the page showing its target here.
  - Web, mail and `rmr:` links open outside. Links with other schemes are ignored rather than handed to the system.
- **Links inside EPUBs:**
  - The tablet's PDF of an EPUB keeps chapter links as bare file names (`story_0002.xhtml`) with no page. Every chapter starts on a new page under its title.
  - A click goes to the first later page that opens with the link's text, compared letter by letter with a little slack for ligatures the text extraction drops (`ChapterLinks`). The page openings are read once, off the main thread, from a copy of the PDF.
  - Measured on a 1916-page EPUB: 293 of 293 table-of-contents links resolve, in order. A link that wraps is one annotation per line; the longest text is used.
- **Live refresh:** each account follows `changes()` and refreshes. A notebook window redraws changed pages and offers "Jump to Latest Edit (p. N)" for an edit made off screen.
- **Links open with any window:** a launch that restores only document windows (no Library) used to leave `rmr://` links waiting forever. Any document window now hands over `openWindow`.

## Checked on the real account

- An A4 PDF with margin notes, highlights in a Manning book, a rotated page and an inserted page, a 467-page EPUB, a v5 landscape slide deck.
- Live: a tablet edit redrew the open page; Jump to Latest Edit worked.
- The "Notes" planner PDF (756 pages, 8430 links): index entry 3 jumps to its page 17, and its Index button jumps back.
- "Telex Tárca" EPUB (1916 pages): its table of contents' "Lackfi János: Hétfőember" (a ligature case) jumps to page 39 with no system alert.
- The "Scaling" v5 landscape notebook shows upright and landscape.
- example-2 (an A4 page with /Rotate 90, in a landscape document): the ink lines up with the page.

## Known limits

- An overlay is the page's size, so v6 ink drawn past the page edge is cut off (`ponytail:`).
- A page whose ink fails to load shows none until something redraws it (a zoom, scrolling back), which retries; there's no per-page error, and no lossy-ink badge on PDF pages yet.
- Assembling the PDF takes about 0.3 s on the main thread for 2000 pages.
- An EPUB chapter whose heading differs from its table-of-contents entry, or a link to a place inside a chapter, goes nowhere.
- The ink cache of an open PDF isn't bounded; it holds only viewed pages that have ink.
